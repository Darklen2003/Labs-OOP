# Dungeon Rogue: Depths of OOP

Пошаговый консольный рогалик (Terminal Roguelike), разработанный в рамках курса «Объектно-ориентированное программирование для разработки компьютерных игр». Проект спроектирован как расширяемая архитектурная база для практической отработки принципов SOLID, абстрактных интерфейсов и чистой архитектуры на Python.

## Архитектура

Архитектурный фундамент проекта (Модуль 2) построен на четырёх ключевых концепциях:

1. **Базовый класс `GameObject` (`core/game_object.py`):**

   * Абстрактный базовый класс (`abc.ABC`), задающий общий жизненный цикл всех физических сущностей (`Player`, `Monster`, `Chest`, `Trap`).

   * Автоматически инкрементирует и присваивает уникальный целочисленный идентификатор `id`.

   * Инкапсулирует состояние активности (`active`, `deactivate()`).

   * Обязывает подклассы реализовать абстрактные методы `update(dt: float)` и `draw() -> str`.

   * Защищён от прямого создания экземпляров на уровне рантайма.

2. **Протоколы способностей (`core/protocols.py`):**

   * **`Movable`**: способность перемещения по координатам (`move(dx, dy)`). Реализуется динамическими объектами (`Player`, `Monster`).

   * **`Drawable`**: способность возвращать глиф/символ для отображения (`draw() -> str`).

   * **`Collidable`**: определяет радиус столкновения (`collision_radius`) и проверку дистанции (`collides_with(other)`).

   * Все протоколы декорированы `@runtime_checkable`, что позволяет валидировать соответствие контракту через `isinstance()` во время выполнения.

3. **Конфигурации (`core/config.py`):**

   * `GameConfig`: глобальные правила сессии (размер карты, лимит ходов, расход энергии на шаг, урон ловушек).

   * `PlayerConfig` и `MonsterConfig`: неизменяемые спецификации параметров сущностей (`frozen=True`).

   * `RoomConfig`: конфигурация комнаты с независимыми коллекциями сущностей и лута (`field(default_factory=list)`).

4. **Миксин логирования (`core/mixins.py`):**

   * `LoggingMixin` подключается первым в цепочке наследования (MRO) игровых сущностей.

   * Не создаёт `__dict__` и оптимизирует память за счёт `__slots__ = ()`.

   * Форматирует вывод сообщений в формате `[ИмяКласса] УРОВЕНЬ: сообщение`.

# Настройка уровней сложности и баланса

В архитектуре проекта сложность настраивается исключительно за счёт того, **какие именно объекты конфигов передаются в игру на этапе её запуска** в файле `config.py`, по стандарту на выбор даётся 3 уровня сложности ихз пресетов.
---

## 1. Рычаги игрового баланса

Сложность складывается из комбинации параметров трёх основных конфигураций:

### 1. `GameConfig` — правила окружающего мира
* **`max_turns`**: лимит ходов на игровую сессию. Чем меньше значение, тем выше темп игры и тем быстрее игроку приходится принимать тактические решения.
* **`step_energy_cost`**: расход выносливости на 1 шаг. При значениях `2` или `3` герой быстрее истощается и вынужден делать паузы на отдых, рискуя попасть под удар монстров.
* **`trap_damage`**: урон от ловушек при наступании. Определяет цену ошибки при невнимательном исследовании подземелья.

### 2. `PlayerConfig` — параметры героя
* **`max_hp`**: максимальный запас здоровья. Задаёт «право на ошибку» в ближнем бою и при срабатывании ловушек.
* **`max_energy`**: максимальный запас энергии. Определяет мобильность и дальность непрерывного перемещения без отдыха.
* **`base_attack`**: базовый урон героя. Задаёт количество ударов, необходимое для устранения противников.

### 3. `MonsterConfig` — параметры противников
* **`max_hp`**: живучесть монстров.
* **`attack_power`**: опасность и наносимый урон за атаку.
* **`aggro_radius`**: дистанция агро (обнаружения). Определяет радиус, в пределах которого монстр замечает героя и начинает преследование.

## Логирование


По умолчанию логи направляются в стандартный поток вывода консоли (`sys.stdout`). Изменить уровень Логирования можно в файле `main.py`

### Управление выводом

* **Фильтрация по уровню (отключение подробных логов):**
  Чтобы отключить сообщения `INFO` и оставить только предупреждения и ошибки (`WARNING`, `ERROR`):

  ```
  import logging
  logging.getLogger().setLevel(logging.WARNING)
  
  ```

* **Полное отключение логирования:**
  Для подавления любых логов (например, во время прогона UI-тестов):

  ```
  import logging
  logging.disable(logging.CRITICAL)
  
  ```

* **Перенаправление логов в файл:**
  Чтобы записывать ход игры в отдельный файл `game.log`:

  ```
  import logging
  logging.basicConfig(
      filename="game.log",
      filemode="w",
      level=logging.INFO,
      format="%(asctime)s [%(name)s] %(levelname)s: %(message)s",
      force=True,
  )
  
  ```

```
├── core/                   # Базовые архитектурные контракты движка
│   ├── config.py           # Dataclass-конфигурации (GameConfig, PlayerConfig и др.)
│   ├── game_object.py      # Абстрактный базовый класс GameObject
│   ├── mixins.py           # LoggingMixin для сквозного логирования

├── entities/               # Конкретные игровые сущности
│   ├── environment.py      # Объекты карты (Chest, Trap)
│   ├── monsters.py         # Враждебные сущности (Monster)
│   └── player.py           # Управляемый персонаж (Player)
├── docs/                   # Архитектурная документация
│   ├── adr_002_game_object.md  # Architecture Decision Record
│   ├── analysis_module2.md     # Анализ кодовой базы до и после рефакторинга
│   └── uml_module2.md          # UML-диаграмма классов (Mermaid)
├── tests/                  # Набор тестов (pytest)

│   ├── test_game_object.py
│   ├── test_mixins.py
│   └── test_protocols.py

```

## Установка и запуск

1. **Создайте и активируйте виртуальное окружение:**

   ```
   python -m venv .venv
   source .venv/bin/activate  # Для Windows: .venv\Scripts\activate
   
   ```

2. **Установите зависимости проекта:**

   ```
   pip install -r requirements.txt
   
   ```

3. **Запустите игру:**

   ```
   python main.py
   
   ```

4. **Запустите тесты:**

   ```
   pytest -v
   
   ```
